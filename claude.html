🔺 三大搜索源互补关系：
米游社百科 (baike.mihoyo.com) — 官方游戏数据，内容最详尽（武器/圣痕数值等），使用数字编号系统，需要名称→编号映射字典才能精确搜索。是 RAG 知识库的主要数据源，但持续更新导致 RAG 快照可能过时。
B站wiki (wiki.biligame.com) — 名字即编号（米游社的"名字友好版"），内容大幅缩水，但适合快速定位已知事物。
萌娘百科 (zh.moegirl.org.cn) — 玩家社区视角，情感细节丰富，非常详细，但缺游戏内部数据（武器数值等）。米游社 + 萌娘百科 = 数据 + 情感 = 完整知识。

TTS 架构亮点

  • 子进程隔离：模型加载/推理不阻塞 FastAPI 主进程
  • 透明代理：Qwen3TTSRemoteProxy 实现相同接口，调用方无感知
  • 自动重启：daemon 线程每30s ping worker，无响应则重启
  • 双启动保护：_worker_starting 标志防止并发启动
  • 量化支持：--quantize 8bit|4bit|none，失败自动回退 bf16
  • 选择性量化：code_predictor/speaker_encoder/codec_head 保持 BF16
  • 异步播放：Popen 不阻塞 Agent 后续回复
  • GGUF就绪：资产完整，待 llama.cpp 合入即可切换

解决的问题

  • 问题1：对话文本污染
    "好的，我来执行..." → 截断前缀
  • 问题2：Action+Final混合
    "Action: xxx + Final Answer: xxx" → 截断
  • 问题3：虚构完整ReAct循环
    LLM生成多步Action+虚构Observation → 只保留第一步

循环检测

QueueStreamingHandler._check_repeat_loop()

  • 跟踪最近 3 次 (tool_name, tool_input)
  • 连续 3 次相同 → llm._force_stop = True
  • RouterLLM._call() 检查标志位 → 返回终止 Final Answer
  • 不使用 RuntimeError (被 LangChain 降级为 WARNING)
